# Evidence

This directory contains evidence generated by running the system end-to-end
against the mock demo banking app (`demo_app/`). It demonstrates both the
LLM-driven discovery path and the deterministic, no-LLM replay path,
including all three replay outcome categories.

## `evidence/discovery/`

Logs and screenshots from a real LLM-driven discovery run against the demo
banking app (`python3 -m src.main discover`). The agent was given only a
natural-language goal and the starting URL — no scripted steps — and had to
figure out each action itself, calling the Claude API at every step.

- `evidence/discovery/<session_id>/discovery_log.json` — the full step-by-step
  reasoning trace (one entry per action) plus the run's final outcome.
- `evidence/discovery/<session_id>/screenshots/` — one screenshot per step,
  in order, showing what the agent saw before each action.
- A successful run (`outcome: "goal_complete"`) also emits a generated
  artifact into `saved_artifacts/` (see below).
- Loose `discovery_<run_id>_<timestamp>.json` files at the top level of this
  folder are per-run summaries auto-captured by the observability module
  (`src/safety/evidence.py`) for *every* discovery run in this session,
  including one earlier run that hit `max_steps_reached` before it guessed
  the login password (the goal text didn't include credentials). That
  superseded run's full session folder was removed; the successful,
  goal-complete run is the one referenced above.

## `evidence/replay/`

Successful deterministic replay, with no LLM calls at all
(`python3 -m src.main replay`). This replays a saved artifact's exact
recorded steps against a live browser and extracts structured outputs.

- `replay_success_result.json` — full `ExecutionResult` for a successful run
  of `saved_artifacts/open_new_account.json` against member `M-1001`:
  `outcome.type == "success"` with extracted outputs `member_name`,
  `account_type`, and `initial_deposit`.
- Loose `replay_<run_id>_<timestamp>.json` files are the same
  auto-captured per-run observability records described above, including
  two earlier runs from before a bug fix (the artifact was missing the
  `extract` steps needed to populate `outputs`); the final,
  fixed run is `replay_success_result.json`.

## `evidence/failure/`

Replay runs demonstrating the other two possible outcomes — a normal,
expected business result and a genuine system/environment failure — to show
the replay engine tells these apart instead of treating every non-success
as an error.

- `replay_business_outcome_result.json` — replaying the same artifact with
  a nonexistent member (`M-9999`) yields `outcome.type == "business_outcome"`,
  `outcome_name == "member_not_found"`. This is not a crash or an error: the
  app correctly reported "member not found" and the replay engine correctly
  classified it as an expected business result, extracting `member_id` from
  the input as context.
- `replay_hard_failure_result.json` — replaying against the same artifact
  with the demo app's Flask server stopped yields `outcome.type ==
  "hard_failure"`, with `failed_step_id`, `expected`/`observed` page state,
  and a `screenshot_path` pointing at the accompanying `.png` in this folder.
  This is a genuine environment failure (the target is unreachable), clearly
  distinguished from the business outcome above.

## `saved_artifacts/`

- `open_new_account.json` — the hand-written reference artifact used for all
  three replay runs above (log in, look up a member, open a new Savings
  sub-account, extract confirmation data).
- `log_in_with_username_admin_and_password_admin123.json` and
  `log_in_to_the_member_portal_using_username.json` — artifacts
  auto-generated by the discovery agent (`emit_artifact`) from its own
  successful recorded sessions, one per discovery run in `evidence/discovery/`.
